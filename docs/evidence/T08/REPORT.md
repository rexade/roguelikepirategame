## Delivered Behaviour

The game is now one playable scene instead of isolated fixtures:

`Bootstrap` title menu (Continue voyage / New campaign / Ocean test / Quit) ->
`OceanWorld`: dock at Homeward Harbor -> refit/upgrade -> embark -> sail, salvage
barrels and wrecks, fight raiders and gunners, loot the wrecks of sunk ships ->
dock to bank cargo (or sink and lose it) -> upgrade -> embark again. Every step
is saved to disk and survives quitting.

| Area | Implementation |
| --- | --- |
| Persistence (`Assets/_Game/Persistence/`) | `JsonSaveStore : ISaveStore`. Schema-1 DTO envelope (`SaveFile.cs`), Newtonsoft with type names disabled, structural validation (`SaveMapper`), content validation through `CampaignSession.ValidateSnapshot`. Commit = same-volume temp write with write-through flush, read-back verification, `File.Replace` keeping the previous committed snapshot as `campaign.backup.json`. Revision compare rejects stale candidates; identical retry is idempotent. Load falls back to the backup and preserves an unreadable main file as `campaign.unreadable-<utc>.json`; unsupported schemas are reported and never overwritten. A new campaign moves existing files aside (`*.replaced-<utc>.json`). |
| Composition (`Assets/_Game/Bootstrap/Composition/`) | `GameDirector` owns the single `CampaignSession`, the store and `IWorldArrival`. Arrival rebuilds salvage and enemies from the saved ledger, binds a fresh `CombatWorld` per voyage and calls `CombatWorld.Restore` on resume. |
| Coherent checkpoints | Taken only at idle tick boundaries with a fresh `CombatWorld.Capture`: every 10 s at sea, immediately before each pickup (so the pickup save describes one instant), after enemy defeats (adding the wreck), on pause, exit-to-title and application quit. |
| Voyage planning | `ExpeditionPlanner`: new voyages seed all authored salvage and place enemies at the authored encounter markers; ship types come from a SplitMix64 stream whose state is saved as the voyage RNG. Encounter 01 = one ship, encounter 02 = an escorted pair. Geography never varies. |
| Enemy wrecks | A defeated ship produces a generated `wreck` entity (`EntityId.Generated(voyage, "wreck/<spawn>")`) with the enemy row's `wreckLoot` (raider 2 wood 1 iron, gunner 3 wood 2 iron), committed through the captured-checkpoint overload. |
| Docking | Press E inside a berth: assisted braking, then `RequestDock` once below 80 % of the berth speed limit; damage still resolves first in `CompleteTick`. |
| Sinking | Zero health commits Sink; a results card explains the lost cargo, the camera lingers on a sinking copy of the hull, the ship is refitted free at the last safe harbor. |
| HUD / menus (`Assets/_Game/UI/Game/`) | Hull and hold meters, cargo detail, weapon/brace cooldown slots, context prompts ("[E] Salvage wreck — 2 wood, 1 iron", "Hold too full…"), enemy health bars, off-screen marker to the nearest friendly harbor, toasts, pause/results/error cards with Retry for frozen saves or arrivals. |
| Presentation | Shots with trails, muzzle flash/smoke, splashes vs impacts, brace ring, sinking hulls, aim marker, speed-driven stern wake decals (`ShipWake`). Visual only (INV-14). |
| Production content | `Content/Production/GameCatalog.asset` (cutter hull, cannon/repeater/brace, hubs, 5 upgrades in 3 tracks) and `GameCombat.asset`; regenerated by `WorldAuthoring.CreateAll`. |
| Scene | `Scenes/OceanWorld.unity`, generated from the approved T02 water scene and `FirstRegion.asset` by `WorldAuthoring` (T02 island kit sized to the T06 collision footprints, shore foam, harbor village, pier and berth ring). |
